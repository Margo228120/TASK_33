# День 3. API

Вчера ты доставал данные ООО «Рога и Копыта» SQL-запросами в pgAdmin. Но сайт, мобильное приложение и программа для компьютера, которые ты будешь делать в следующие дни, не умеют открывать pgAdmin. А давать им пароль от базы — всё равно что раздать ключи от склада всем покупателям.

Поэтому между базой и приложениями ставят посредника — **API**. Его уже написал программист-стажёр компании на языке **C#**. Стажёр торопился и наделал ошибок, а потом уволился. Твоя задача — **найти и исправить его ошибки**.

> 💡 Сегодня не нужно уметь программировать. Нужно внимательно читать, сравнивать «что должно быть» с «что получилось» и рассуждать. Это и есть главное умение программиста.

### Что такое API — за одну минуту

```
 сайт  ─┐                                 ┌──────────┐   SQL    ┌──────────┐
 моб.  ─┼── «дай товар 17» ─── HTTP ────► │   API    │ ───────► │   база   │
 прога ─┘ ◄── {"id":17,"name":"..."} ──── │ (сегодня)│ ◄─────── │   shop   │
                                          └──────────┘          └──────────┘
```

- **API** — программа, которая принимает запросы от других программ и отвечает им. Внутри она сама ходит в базу.
- **HTTP** — язык, на котором браузер разговаривает с сайтами. API говорит на нём же. Каждый **запрос** — это **метод** и **адрес**: `GET /products/17`.
- **Метод** говорит, *что* сделать:

| Метод | Что делает | Похоже на SQL |
|---|---|---|
| `GET` | получить данные | `SELECT` |
| `POST` | добавить новое | `INSERT` |
| `PUT` | изменить | `UPDATE` |
| `DELETE` | удалить | `DELETE` |

- **Адрес** (путь) говорит, *с чем*: `/products` — все товары, `/products/17` — товар номер 17.
- **JSON** — формат, в котором API отвечает. Его легко читать и людям, и программам:

```json
{"id": 17, "name": "Кофемашина ZOLOTO-3000", "categoryId": 4, "price": 89900, "stock": 2}
```

`{ … }` — один объект (одна строка таблицы), `[ … ]` — список объектов.

- **Код ответа** — число, по которому сразу видно, получилось или нет: `200` — всё хорошо, `404` — такого нет, `400` — ты прислал что-то не то, `500` — ошибка внутри API. Полная таблица будет в части C.

### Что такое EF Core — за одну минуту

SQL в коде API почти не встретится. За программиста его пишет **Entity Framework Core** (EF Core) — библиотека, которая переводит обычный код на C# в SQL:

```csharp
db.Products.Where(p => p.Price > 1000).OrderBy(p => p.Price).ToList()
```

```sql
SELECT * FROM products WHERE price > 1000 ORDER BY price
```

А строки, которые вернула база, EF Core сам превращает в объекты C#, а ASP.NET — в JSON. Вчерашний SQL не пропадёт: ты увидишь, какой SQL составляет EF Core, и это поможет понять, где ошибка.

## Шаг 3. Расскажи API, как попасть в базу

Чтобы подключиться к базе, API нужна **строка подключения**: где сервер, какая база, какой пользователь и пароль.

Её **нельзя** писать прямо в код: твой репозиторий на GitHub видят все, и пароль увидят тоже. Поэтому положим её в **секреты пользователя** — специальный файл на твоём компьютере, который живёт отдельно от проекта и никогда не попадёт в Git.

В Git Bash, в папке `TASK_3`, выполни одну команду. Вместо `ТВОЙ_ПАРОЛЬ` подставь пароль пользователя `postgres`, который ты придумал во второй день при установке PostgreSQL (тот же, что вводил в pgAdmin):

```bash
dotnet user-secrets set "ConnectionStrings:Shop" "Host=localhost;Port=5432;Database=shop;Username=postgres;Password=ТВОЙ_ПАРОЛЬ"
```

```
Successfully saved ConnectionStrings:Shop to the secret store.
```

- `ConnectionStrings:Shop` — имя секрета. В `Program.cs` API ищет строку подключения именно по имени `Shop`.
- `Host=localhost` — сервер базы на этом же компьютере, `Port=5432` — порт из установки PostgreSQL, `Database=shop` — база из второго дня.
- Кавычки обязательны. Пробелов внутри строки быть не должно.

Ошибся в пароле — просто выполни команду ещё раз с правильным.

## Шаг 5. Как устроен проект

Вот что происходит, когда приходит запрос `GET /categories`:

```
 GET /categories
       │
       ▼
 Controllers/CategoriesController.cs     контроллер: принимает запрос и решает, что ответить
       │   db.Categories.OrderBy(c => c.Id).ToList()
       ▼
 Data/ShopContext.cs, Models/*.cs        EF Core: переводит это в SQL, а строки из базы — в объекты
       │   SELECT ... FROM categories ORDER BY id
       ▼
 база shop
```

### Модели

Открой папку `Models`. В ней — по классу на каждую таблицу базы:

```csharp
public class Product
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
    public int CategoryId { get; set; }
    public int Price { get; set; }
    public int Stock { get; set; }
}
```

- `class Product` — тип данных «Товар». Один объект `Product` — одна строка таблицы `products`.
- Каждая строчка внутри — **свойство**, то есть столбец. `int` — целое число, `string` — текст, `DateOnly` — дата.
- Свойство `CategoryId` — это столбец `category_id`: EF Core убирает подчёркивания и начинает каждое слово с большой буквы.
- В JSON свойство `CategoryId` превратится в `categoryId` — с маленькой буквы. Так принято в JSON.

API отдаёт строки таблиц как есть: товар — это `{"id":…, "name":…, "categoryId":…, "price":…, "stock":…}`, заказ — `{"id":…, "clientId":…, "orderDate":…, "status":…}`. Никаких дополнительных полей.

### Контекст базы

`Data/ShopContext.cs` связывает модели с таблицами:

```csharp
public DbSet<Product> Products => Set<Product>();
```

Это значит: `db.Products` — таблица `products`. Через `db` код читает и меняет все таблицы.

### Контроллер

Открой `Controllers/CategoriesController.cs`. Первый метод в нём — **правильный пример**, в нём ошибок нет:

```csharp
[ApiController]
[Route("categories")]
public class CategoriesController(ShopContext db) : ControllerBase
{
    // Пример. GET /categories — все категории
    [HttpGet]
    public List<Category> GetAll()
    {
        return db.Categories.OrderBy(c => c.Id).ToList();
    }
}
```

Разберём по строчкам:

- `[ApiController]` и `[Route("categories")]` — **атрибуты**, пометки в квадратных скобках. Они говорят: «этот класс отвечает на запросы, адреса которых начинаются с `/categories`».
- `[HttpGet]` — «этот метод отвечает на запрос `GET`» по адресу контроллера, то есть `GET /categories`.
- `public List<Category> GetAll()` — **метод** с именем `GetAll`, который возвращает **список** категорий (`List<Category>`).
- `db.Categories.OrderBy(c => c.Id).ToList()` — «возьми таблицу категорий, отсортируй по `Id` и выполни запрос». ASP.NET сам превратит список в JSON.

`c => c.Id` — это **лямбда**, маленькая функция: «для каждой категории `c` возьми её `Id`». Имя `c` можно выбрать любое: `x => x.Id` работает так же.

> ⚠️ **`.ToList()` в конце обязателен.** Без него запрос только *описан*, но не выполнен — в базу ничего не уйдёт.

Над каждым методом стоит комментарий (строка после `//`): что этот метод **должен** делать. Это и есть условие задачи. Код под ним делает то, что **на самом деле** написал стажёр. Твоя работа — найти, где они расходятся.

| Файл | Адреса | Задания |
|---|---|---|
| `Controllers/ProductsController.cs` | `/products/...` | 1, 2, 8, 9, 10, 13* |
| `Controllers/ClientsController.cs` | `/clients/...` | 3, 7 |
| `Controllers/CategoriesController.cs` | `/categories/...` | 4 |
| `Controllers/OrdersController.cs` | `/orders/...` | 5, 6, 11, 12 |

### Правила C#, которые сэкономят тебе нервы

- Каждая команда заканчивается точкой с запятой `;`. А после `}` метода точка с запятой не нужна.
- Большие и маленькие буквы различаются **везде**: `Product` и `product` — разные имена.
- Текст пишется в **двойных** кавычках: `"Казань"`.
- `null` — «пусто, ничего нет». Например, если товар не нашёлся.
- Ошибки Visual Studio подчёркивает **красной** волнистой линией, а предупреждения — **зелёной**. Полный список — в окне **Список ошибок** (Error List) внизу. Наведи мышку на подчёркнутое место — появится объяснение.

**Сравнения и логика** — тут прячется половина ошибок:

| Запись | Значит | Пример |
|---|---|---|
| `a == b` | равно (**два** знака!) | `c.City == "Казань"` |
| `a != b` | не равно | `product != null` — «товар нашёлся» |
| `a < b`, `a > b` | меньше, больше | `5 < 5` — это **ложь** |
| `a <= b`, `a >= b` | меньше или равно, больше или равно | `5 <= 5` — это **правда** |
| `a && b` | И: правда, только если правда **оба** | `p.Price > 100 && p.Stock > 0` |
| `a \|\| b` | ИЛИ: правда, если правда **хотя бы одно** | `p.Price > 100 \|\| p.Stock > 0` |
| `!a` | НЕ: превращает правду в ложь и наоборот | `!db.Clients.Any(…)` — «такого клиента нет» |

Один знак `=` — это «присвоить», а не «сравнить»: `product.Price = 500` записывает в цену 500.

**`if`** — «если»: выполнить следующую строку, только когда условие в скобках правда.

```csharp
if (product == null)        // если товар не нашёлся,
    return NotFound();      // ответить 404 и больше ничего не делать
```

`return` сразу заканчивает метод: строки под ним уже не выполнятся.

## Шаг 6. Как искать ошибку

Профессиональные программисты ищут ошибки всегда одинаково. Делай так же в каждом задании:

1. **Прочитай условие** — в README и в комментарии над методом. Пойми, что API *должен* ответить.
2. **Запусти и посмотри**, что API отвечает *на самом деле*. Попробуй разные варианты, а не только пример из задания.
3. **Сравни.** Что именно не так? Не тот код ответа? Лишние строки? Не тот порядок? Не то число?
4. **Найди строку**, которая за это отвечает. Читай код метода сверху вниз и для каждой строки спрашивай себя: «что она делает? это то, что требует условие?». Подсказки:
   - если API ответил `500` — в чёрном окне сервера есть красное слово `fail` и под ним описание ошибки;
   - если ответ неправильный — посмотри в чёрном окне, какой SQL отправил EF Core. Такой ли SQL ты бы написал сам во второй день?
5. **Исправь** как можно меньше: обычно ошибка — это одно слово, один знак или одна строка. Переписывать метод целиком не нужно.
6. **Перезапусти API и проверь ещё раз** — и пример из задания, и свои варианты. Исправление одной ошибки иногда открывает следующую.
7. **Запиши в `REPORT.md`**, что было не так и что ты исправил.

> 💡 В каждом задании сказано, **сколько в нём ошибок**. Нашёл меньше — ищи дальше. Ошибки есть только в тех методах, о которых говорится в задании.

> 💡 Подсказки «Проверь себя» — это то, что API должен отвечать **после** исправления.

## Часть A. Первые ошибки

### Шпаргалка

**SQL → EF Core.** Почти всё, что ты вчера писал в SQL, есть и в EF Core:

| SQL | EF Core |
|---|---|
| `SELECT * FROM products` | `db.Products.ToList()` |
| `WHERE price > 1000` | `.Where(p => p.Price > 1000)` |
| `WHERE city = 'Тула' AND id > 3` | `.Where(c => c.City == "Тула" && c.Id > 3)` |
| `ORDER BY price` | `.OrderBy(p => p.Price)` |
| `ORDER BY price DESC` | `.OrderByDescending(p => p.Price)` |
| `LIMIT 5` | `.Take(5)` |
| `SELECT COUNT(*)` | `.Count()` |
| «есть ли хоть одна такая строка?» | `.Any(c => c.Id == 3)` → `true` (правда) или `false` (ложь) |
| одна строка по `id` | `db.Products.Find(17)` → объект или `null` |
| первая подходящая строка | `.FirstOrDefault(c => c.Name == "Мебель")` → объект или `null` |

Части соединяются в цепочку: `db.Products.Where(…).OrderBy(…).ToList()`.

**Параметр в адресе.** Часть адреса в фигурных скобках становится переменной:

```csharp
[HttpGet("{id}")]                     // адрес /categories/{id}
public ActionResult<Category> Get(int id)
```

- `{id}` в адресе и `int id` в скобках метода — одно и то же. Для адреса `/categories/3` в переменной `id` окажется `3`.
- Слово перед именем переменной — её **тип**: `int id` — целое число, `string city` — текст. Тип должен совпадать с тем, что в этой переменной на самом деле хранится.
- `ActionResult<Category>` — «вернёт либо **одну** категорию, либо код ошибки». А `List<Category>` — **список** категорий.
- `return NotFound();` — ответить кодом `404`. `return category;` — кодом `200` и данными.

**Параметр после знака `?`.** Адрес может нести дополнительное условие: `/clients?city=Казань`. Такой параметр тоже пишется в скобках метода, но в атрибуте его нет. `string? city` — текст, который может отсутствовать: если в адресе нет `?city=…`, в переменной будет `null`.

> 💡 Русские буквы в адресной строке браузера работают: просто напиши `http://localhost:5000/clients?city=Казань`.

## Часть C. Изменяем данные

До сих пор API только *отдавал* данные. Теперь он будет их принимать и менять.

### Шпаргалка

**Данные в запросе.** `POST` и `PUT` присылают данные в **теле** запроса — в формате JSON. Если в скобках метода есть параметр-модель, ASP.NET сам превратит JSON в объект:

```csharp
[HttpPost]
public ActionResult<Category> Create(Category c)     // c — объект из тела запроса
{
    db.Categories.Add(c);        // «добавь эту категорию» — пока только в памяти программы
    db.SaveChanges();            // отправить изменения в базу: только здесь выполнится INSERT
    return Created($"/categories/{c.Id}", c);
}
```

- `db.Categories.Add(…)`, `db.Categories.Remove(…)`, изменение свойств (`product.Price = 500`) — всё это пока только **в памяти программы**. В базе ничего не поменялось.
- `db.SaveChanges()` — **записать в базу всё, что накопилось**. Без него база не узнает об изменениях. После него в `c.Id` окажется номер, который придумала база.
- `$"/categories/{c.Id}"` — строка со вставкой значения: `{…}` внутри заменится на номер.

**Коды ответа:**

| Код | Как вернуть | Когда |
|---|---|---|
| `200 OK` | `return данные;` | всё хорошо, вот данные |
| `201 Created` | `return Created(адрес, данные);` | создано новое, вот оно |
| `204 No Content` | `return NoContent();` | всё хорошо, но отдавать нечего (например, после удаления) |
| `400 Bad Request` | `return BadRequest("что не так");` | в запросе ошибка: пустое название, отрицательная цена… |
| `404 Not Found` | `return NotFound();` | такого нет |
| `409 Conflict` | `return Conflict("почему");` | запрос правильный, но выполнить его нельзя из-за других данных |
| `500 Internal Server Error` | сам не возвращай | API упал с ошибкой. Ищи её в чёрном окне сервера |

**Как отправить `POST` или `PUT` в Swagger:** нажми на эндпоинт → **Try it out** → в поле **Request body** напиши JSON → **Execute**. Swagger подставит пример со всеми полями — просто поменяй значения. Поле `id` оставь `0`.

## Часть D. Заказы

### Шпаргалка

**Порядок важен.** Код метода выполняется сверху вниз, строка за строкой. Вспомни шпаргалку части C: `db.SaveChanges()` сразу записывает в базу всё, что накопилось. Если после этого метод вернёт `400` — то, что уже записано, **так и останется в базе**. `return` ничего не отменяет.

```csharp
foreach (var line in input.Items)
{
```

**Список значений и проверка «есть ли в нём»:**

```csharp
string[] colors = ["красный", "зелёный", "синий"];
if (!colors.Contains(color))
    return BadRequest("Нет такого цвета");
```

> Проверь себя: код `201`, в ответе новый `id` (23, если ты проходил проверки по порядку), а `/products/1` — по-прежнему пончики.

Заполни `REPORT.md`, закоммить, запушь.

## Если что-то пошло не так

Ошибки C# Visual Studio показывает в окне **Список ошибок** (Error List), а ошибки во время работы API — в чёрном окне сервера. Ошибки бывают по-английски или по-русски — ниже оба варианта.

<details>
<summary>При запуске окно «Возникли ошибки сборки. Продолжить?» / <code>There were build errors. Would you like to continue?</code></summary>

В коде есть ошибки, и Visual Studio не может собрать API. Нажми **Нет** (No), открой окно **Список ошибок** (Error List) — меню **Вид** (View) → **Список ошибок** — и исправляй ошибки по одной, начиная с первой. В задании 1 так и должно быть.
</details>

<details>
<summary><code>dotnet: command not found</code></summary>

Git Bash открыт ещё со времён до установки Visual Studio. Закрой его и открой заново. Если не помогло — открой **Visual Studio Installer** и проверь, что стоит галочка **ASP.NET и разработка веб-приложений** (шаг 1).
</details>

<details>
<summary>Код <code>500</code> и в окне сервера <code>The ConnectionString property has not been initialized</code> / <code>Свойство ConnectionString не было инициализировано</code></summary>

API не нашёл строку подключения. Выполни команду из шага 3 ещё раз — **в папке `TASK_3`** (проверь командой `pwd`). Имя секрета должно быть ровно `ConnectionStrings:Shop`.
</details>

<details>
<summary><code>28P01: password authentication failed for user "postgres"</code> / <code>пользователь "postgres" не прошёл проверку подлинности</code></summary>

Неверный пароль в строке подключения. Выполни команду из шага 3 ещё раз с правильным паролем — тем, что во второй день вводил в pgAdmin.
</details>

<details>
<summary><code>3D000: database "shop" does not exist</code> / <code>база данных "shop" не существует</code></summary>

Базы `shop` нет — создай её, как в шаге 2 дня 2, и выполни `shop.sql`.
</details>

<details>
<summary><code>42P01: relation "products" does not exist</code> / <code>отношение "products" не существует</code></summary>

База `shop` есть, но таблиц в ней нет. Выполни `shop.sql` (шаг 2). Проверь, что в заголовке Query Tool написано `shop/postgres@…`, а не `postgres/postgres@…`.
</details>

<details>
<summary>В Swagger код <code>500</code></summary>

API упал при обработке запроса. Найди в чёрном окне сервера красное слово `fail` — под ним написано, что случилось. Самая полезная строчка обычно та, что начинается с названия ошибки: `System.ArgumentException: …`, `Npgsql.PostgresException: …`. Прочитай её целиком — часто там прямо сказано, что не так.
</details>

<details>
<summary>Адрес отвечает <code>404</code>, хотя метод есть</summary>

- API не перезапущен после изменения кода.
- Метод сам возвращает `NotFound()` — проверь условие `if` перед этим `return`.

Посмотри в Swagger: там перечислены все адреса, которые API знает.
</details>

<details>
<summary><code>CS1002: ; expected</code> / <code>Требуется ";"</code></summary>

Пропущена точка с запятой. Visual Studio подчёркивает место ошибки — `;` нужна в конце строки.
</details>

<details>
<summary><code>CS0029: Cannot implicitly convert type '…' to '…'</code> / <code>Не удается неявно преобразовать тип "…" в "…"</code></summary>

Метод обещает вернуть одно, а возвращает другое. Например, в объявлении метода написано, что он вернёт **список** товаров (`List<Product>`), а в `return` стоит **один** товар. Сравни тип в объявлении метода с тем, что на самом деле стоит после `return`, и с тем, что метод должен делать по условию.
</details>

<details>
<summary><code>CS0266: Cannot implicitly convert type 'System.Linq.IQueryable&lt;…&gt;' to 'System.Collections.Generic.List&lt;…&gt;'</code></summary>

В конце запроса забыт `.ToList()`. Без него запрос не выполняется — и это ещё не список.
</details>

<details>
<summary><code>CS0103: The name '…' does not exist in the current context</code> / <code>Имя "…" не существует в текущем контексте</code></summary>

Опечатка в имени, или переменная объявлена в другом месте. Помни: большие и маленькие буквы различаются.
</details>

<details>
<summary>Зелёное подчёркивание: <code>CS8602: Dereference of a possibly null reference</code> / <code>Разыменование вероятной пустой ссылки</code></summary>

Это предупреждение, а не ошибка: API запустится. Но Visual Studio считает, что в этом месте переменная может оказаться `null` — то есть объект не нашёлся. Если в этот момент обратиться к его свойствам, API упадёт с `NullReferenceException`. Подумай, при каком условии код доходит до этой строки.
</details>

<details>
<summary><code>NullReferenceException: Object reference not set to an instance of an object</code> / <code>Ссылка на объект не указывает на экземпляр объекта</code></summary>

Код обратился к свойствам объекта, которого нет, — он равен `null`. Например, товар не нашёлся (`Find` вернул `null`), а код всё равно пытается поменять ему цену. Посмотри на проверки `if (… == null)` перед этим местом.
</details>

<details>
<summary><code>DbUpdateException</code> и <code>23503: … violates foreign key constraint</code> / <code>нарушает ограничение внешнего ключа</code></summary>

База не даёт удалить товар, на который ссылаются строки заказов, — или добавить строку с несуществующим товаром, клиентом или категорией. Это и есть то, что API должен проверять сам **до** `SaveChanges` и отвечать `400` или `409` (задания 8, 10).
</details>

<details>
<summary><code>DbUpdateException</code> и <code>23505: duplicate key value violates unique constraint</code> / <code>повторяющееся значение ключа нарушает ограничение уникальности</code></summary>

Код пытается добавить строку с номером `id`, который в таблице уже занят. Номера новых строк должна придумывать база (задание 13*).
</details>

<details>
<summary><code>Failed to bind to address http://localhost:5000: address already in use</code></summary>

API уже запущен — например, в другом окне Visual Studio или в Git Bash. Закрой старое чёрное окно сервера (или нажми в нём **Ctrl + C**) и запусти снова.
</details>

<details>
<summary>Изменил код, но API работает по-старому</summary>

Останови API (**■** или **Shift + F5**) и запусти снова (**▶** или **F5**).
</details>

<details>
<summary>В Swagger код <code>400</code>, и в ответе есть <code>"errors"</code></summary>

ASP.NET не смог прочитать JSON из тела. Проверь кавычки (в JSON — только двойные), запятые между полями и фигурные скобки по краям. В `"errors"` написано, какое поле не понравилось.
</details>

<details>
<summary>В базе появились лишние товары или заказы</summary>

Пока в коде есть ошибки, API может записывать в базу то, чего не должен. Это нормально — так ошибки и находят. Выполни `shop.sql` (шаг 2), и база станет как новенькая.
</details>
